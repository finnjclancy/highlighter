Long description:

```text
Highlighter connects ChatGPT to the pages, PDFs, and highlight library in your Chrome browser. Ask in natural language and the agent can read an open source, save exact passages as persistent highlights, add notes or tags, organise folders, retrieve a staged Library selection, compare marked evidence across pages, export research, and return a finished live sharing link in the chat.

The connection exposes 24 focused MCP tools. Browser changes use stable highlight IDs and reversible operation IDs where possible. Highlighter remains local-first: saved highlights live in the browser unless a tool returns them to the conversation or you deliberately publish a live link.

Pairing uses OAuth 2.1, PKCE, and a one-time code generated by the Highlighter extension. The private browser token never goes into ChatGPT. No Highlighter account is required.
```

## Positive test cases

### 1. Inspect the active article

- Prompt: `What page is open in Highlighter? List its saved highlights and suggest one additional passage worth marking. Ask before changing it.`
- Setup: Open an ordinary HTTPS article in Chrome with at least one saved highlight and keep Agent connection enabled.
- Expected tools: `get_active_page`, then `get_highlighted_text`; no write tool before approval.
- Expected result: Page title/URL, existing quotes, and one clearly identified suggestion.

### 2. Read and annotate a PDF

- Prompt: `Read pages 1–8 of the PDF open in Highlighter. Highlight the central claim and every explicit limitation, with a short note on each.`
- Setup: Open a selectable PDF in Highlighter's PDF Reader.
- Expected tools: `get_active_page`, one or more `get_pdf_document` calls, then `highlight_passages` with exact quotations.
- Expected result: Persistent PDF highlights with counts; unmatched quotations are reported rather than fabricated.

### 3. Organise a staged Library selection

- Prompt: `Organise the highlights I selected in the Library into folders for claims, evidence, and limitations. Explain the plan, then apply it.`
- Setup: Select at least three highlights in the Library and stage them for chat.
- Expected tools: `get_library_selection`, `list_folders`, then `organize_folders` after the plan is stated.
- Expected result: Updated folder labels plus a reversible operation ID; no highlight text is deleted.

### 4. Compare marked evidence

- Prompt: `Compare my highlights from these two open-source articles. Summarise agreements, contradictions, and unanswered questions with links.`
- Setup: Save highlights on two known HTTPS URLs.
- Expected tools: `compare_pages` with the two exact URLs, optionally `search_highlights` first.
- Expected result: A synthesis grounded only in marked passages, with source links preserved.

### 5. Publish a managed gallery

- Prompt: `Create an unlisted live link called “Launch research” from the current page's highlights, expiring in 14 days, and give me the URL.`
- Setup: Open a page with at least one saved highlight.
- Expected tools: `get_active_page`, then `create_live_link`.
- Expected result: A working `https://highlighter-share.finnjclancy.workers.dev/v/...` URL returned directly; no management credential appears in chat.

## Negative test cases

### 1. Unsupported browser page

- Scenario: The active tab is `chrome://extensions` and the user asks, `Highlight the important settings on this page.`
- Expected behavior: Explain that Chrome blocks extensions on internal pages and ask the user to open a normal HTTP(S) source. Do not claim that highlights were created.
- Why: The Highlighter content script cannot legally or technically attach to internal Chrome pages.

### 2. Inexact or unavailable quotation

- Scenario: The user asks to highlight a paraphrase that does not occur on the target page, or the target page is not open.
- Expected behavior: Use a read tool if the source is available, otherwise ask the user to open it. Do not invent an exact quotation. Report unmatched passages from `highlight_passages` honestly.
- Why: Persistent highlights require exact source text and an attached browser page.

### 3. Ambiguous destructive request

- Scenario: The user says, `Delete the bad highlights` without identifying which highlights are bad.
- Expected behavior: Retrieve stable IDs and ask the user to identify or confirm the intended items before calling `remove_highlights`. Do not bulk-remove on an inferred criterion.
- Why: Removal is consequential even though an operation ID may allow restoration.
